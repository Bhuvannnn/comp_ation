# Supporting review — frontier computer use, HITL/safety, and §3.2 completeness

**Reviewer:** Supporting reviewer (`gpt-5.6-sol-high`)
**Reviewed:** `Project.md`, `frontier_computer_use.md`, `_hitl_safety.md`, and `brief_decomposition.md`
**Verdict:** Endorse the shared architecture direction, with targeted corrections below. This is a review, not a PRD or stack lock.

## 1. Frontier computer-use recommendations

| Major recommendation | Endorsement | Residual risk | One condition that flips me contrarian |
|---|---|---|---|
| Treat frontier CUA as the discovery mechanism, then compile to deterministic replay. | **Strongly endorse.** This is the cleanest reading of Project §§2–3.3. Anthropic/OpenAI-style screenshot loops are useful for finding a path, but rerunning such a loop is not the required model-free production path. | “Compiler” can hide an unreliable inference problem. One trajectory does not automatically reveal which values are parameters, which observations are outputs, or which state is a sufficient checkpoint. Prefer structured tool calls during discovery plus explicit validation/review over unconstrained post-hoc inference. | I would favor a frozen generated program over a separate DSL if it had a machine-readable typed invocation manifest, no model calls, schema validation, reviewable targets/checkpoints, and repeat-run evidence equal to the proposed artifact executor. |
| Use accessibility/ARIA observation first, with screenshots as evidence and a bounded discovery fallback. | **Endorse conditionally.** It is cheap, inspectable, and naturally promotes to role/name/label locators. It is stronger than raw DOM dumps for many pages. | “No clean DOM” does not imply “good accessibility tree.” Legacy tables, canvas, remote desktops, unlabeled controls, and cross-frame content can make the ARIA view incomplete. This choice needs an observed coverage check on the selected target, not only a general claim. | I would switch discovery to visual-first if a target audit showed that the accessibility snapshot omitted or ambiguously represented the controls needed for the vertical slice while screenshot grounding was repeatably accurate. |
| Promote ephemeral refs or discovery coordinates into ranked, durable, frame-aware locator recipes. | **Strongly endorse.** Raw MCP refs and runtime element handles are not serializable capability targets. The artifact should retain semantic intent, ordered candidates, expected match cardinality, and post-resolution validation. | The proposed universal ranking (`role → label → text → structure → CSS`) is not universally robust. Text can be tenant-localized, role/name can be duplicated, and DOM-relative structure can drift. Resolver success must mean “unique and contextually correct,” not merely “one candidate matched.” | I would permit a visual anchor/relative-coordinate locator ahead of semantic locators for a canvas/VDI control if viewport constraints, anchor confidence, uniqueness, and an immediate checkpoint were all enforced deterministically. |
| Implement a hostile local web target; keep native desktop as a credible adapter/design seam. | **Endorse.** It maximizes reproducibility, synthetic-data safety, failure injection, and same-session handoff while still exercising frames/tables/no-test-ID conditions. Project §3.7 expressly makes desktop implementation optional. | A deliberately hostile fixture can become a puzzle tailored to the implementation. It must still have genuine state transitions, realistic exceptional states, and a real model-guided discovery run. An empty `OsDesktopSurface` interface would add theater rather than evidence. | I would choose Electron/native desktop as the concrete target only if the selected business flow fundamentally required OS-level behavior and a stable interactive desktop plus manual takeover was already available. |
| Keep Playwright/custom tools small; do not ship MCP, Stagehand, browser-use, or a lab CUA loop as the production executor. | **Endorse.** Owning the trajectory, policy gate, artifact validator, and executor makes the assignment’s central contracts visible. | Avoiding frameworks can itself become bespoke infrastructure. Reusing a library is fine where its behavior is deterministic and the project still owns artifact semantics and prevents model fallback. | I would adopt a framework in the core path if it exposed the complete typed artifact/replay contract, allowed model fallback to be disabled and tested, and reduced code without obscuring policy or error behavior. |
| Allow at most a bounded pixel click during discovery, followed by hit-test promotion. | **Endorse only as a fallback.** It is a sensible escape hatch for one otherwise inaccessible control. | Hit-testing after a click does not recover a semantic target for canvas, remote-desktop, closed-shadow, or custom-drawn controls; it may return only the canvas/container. “One click then promote” must fail closed when promotion cannot produce a replayable target. | I would allow a persisted pixel-based replay target if it were relative to a stable visual anchor, resolution/DPI constrained, confidence-gated, and immediately followed by a strong checkpoint; raw absolute coordinates still would not qualify. |

### Frontier corrections before synthesis

1. `frontier_computer_use.md` line 324 names `page.accessibility.snapshot()`. Current Playwright documentation exposes `page.ariaSnapshot()` and `locator.ariaSnapshot()` for YAML ARIA snapshots. Use the current API name and distinguish ordinary ARIA snapshots from Playwright MCP snapshots containing ephemeral action refs.
2. Do not claim accessibility snapshots are inherently deterministic. Their serialization is deterministic for a given rendered state, but accessible names, dynamic values, tenant branding, and tree quality can vary.
3. “Screenshot coordinates as replay locators: avoid” is correct for raw absolute points, but too categorical for anchor-relative, resolution-constrained visual targets. Keep those as an explicit last-resort locator variant rather than claiming pixels can never satisfy stable targeting.
4. The OpenAI model/version wording is perishable. The current guide overview still discusses `gpt-5.4`, while its examples now use `gpt-5.6`. The architecture should cite the three harness shapes, not bind its reasoning to a current model label.

## 2. HITL and safety recommendations

| Major recommendation | Endorsement | Residual risk | One condition that flips me contrarian |
|---|---|---|---|
| Use explicit discovery/replay escalation triggers instead of “the model feels stuck.” | **Strongly endorse.** Budgets, repeated-action/state detection, unknown blockers, risky steps, ambiguous writes, and hard failures are concrete and testable. | An allowlist violation is not a human-approvable risky action. It may create an intervention record for review, but the live operator must not bypass policy merely by taking control; policy must be changed through an authorized path first. | I would omit live-session escalation for policy violations if the demo has no legitimate safe manual completion path; aborting with a policy-review record would then be safer and more faithful. |
| Demonstrate same-session handoff with one persistent headed browser and explicit pause/resume. | **Endorse the minimal mechanism, not the CDP exclusivity claim.** Keeping the same process/context/page alive and letting the operator use that visible window satisfies the same-session requirement. | CDP attachment does not grant an exclusive input lease, and a remote-debugging port adds attack surface. A local human can still click while state says `automation`; conversely, CDP does not automatically report physical input as audited semantic actions. `page.pause()` is a useful headed debugging primitive, but by itself proves only that script execution pauses and resumes. | I would require a proxied operator-input channel instead of the literal browser window if the grader must observe enforced mutual exclusion and complete human-action capture rather than a single-user demo with audited state transitions. |
| Model ownership as `automation → transitioning_to_human → human → transitioning_to_automation`, and guard every automation action. | **Endorse.** The transition states correctly make re-observation and failed resume explicit. | A process-local enum enforces only the automation side. It cannot make a visible local browser view-only for the human. The text should say “authorized owner” and document the demo’s enforcement limit rather than claim sole physical control. Also define terminal `cancelled/expired/failed` run states separately from ownership. | I would collapse the transition states into one paused state if transitions are synchronous in the implementation and tests show no observable race or failure point; otherwise the four states earn their complexity. |
| Emit a structured intervention request and re-observe/checkpoint before resume. | **Strongly endorse.** This directly addresses Project §3.6 and prevents continuation from stale state. | The sample payload leaks the very values the safety section says to minimize: raw `goal_text` contains a member ID, and `current_url_or_window_title` embeds it again. DOM/screenshot references can also expose PII. Payload fields need sanitized goal/target summaries, parameter names or opaque tokens, evidence classification, and access/expiry semantics. | I would exclude screenshots/DOM from the request payload entirely if reliable pre-write redaction cannot be demonstrated; a sanitized state code plus separately access-controlled evidence is safer. |
| Record human action types/targets without raw entered values. | **Endorse the data-minimization goal.** Semantic audit events are sufficient for the take-home; keystroke or cursor telemetry is unnecessary. | Physical clicks in a headed browser are not automatically captured as semantic Playwright/CDP commands. DOM listeners can miss browser chrome, cross-origin frames, navigation boundaries, and non-DOM surfaces. Pausing all evidence during takeover can also conflict with the requirement to record what the human did. | I would use operator attestations plus before/after checkpoints instead of inferred per-action logs if the selected takeover channel cannot capture actions reliably without collecting sensitive values. |
| Enforce domain/route/action allowlists at the common action boundary, with per-step risk metadata. | **Strongly endorse, with one required fix.** Policy must gate both discovery and replay immediately before dispatch, and redirects/new windows must be checked again after navigation. | `risk_classification.default: safe` is unsafe and contradicts positive validation. Missing or unknown classification should reject validation or default to `confirm/deny`. URL matching also needs parsed origins, canonical paths, encoded-path handling, and explicit redirect/popup/download policy. | I would move risk out of each artifact step into a centrally signed capability policy if step-level tags could be authored or altered by the same untrusted discovery path; the executor still needs an immutable resolved classification. |
| Use allowlisted structured logs, parameter placeholders, and pre-write evidence redaction. | **Strongly endorse.** This is a practical take-home interpretation of data minimization. Synthetic data does not remove the need to prove the mechanism. | Known-selector blackout is not general screenshot/DOM redaction, and raw goals, URLs, accessible names, text locators, error banners, traces, and output values can all contain PII. Redaction must happen before persistence, with failure-to-redact failing closed. | I would omit screenshots from committed evidence if pre-write redaction cannot be made reliable; Project §3.5 permits a DOM snapshot or trace instead, provided that signal is also sanitized. |
| Represent business outcomes, recoveries, and hard failures in types. | **Strongly endorse the taxonomy; revise the proposed union.** Final replay results should be `success | business_outcome | hard_failure`, with recoveries as ordered events/diagnostics attached to the final result. | A recursive terminal `{ kind: "recovered"; then: ReplayResult }` makes a transient event look like a fourth final outcome and complicates callers. Permission denial and validation errors also require capability-specific classification rather than global text matching. | I would keep `recovered` as a top-level result only if invocation is intentionally suspended after recovery and the caller, rather than the executor, must explicitly continue. |
| Keep artifact definitions reusable while isolating tenant execution context and locator overlays. | **Endorse as design.** Base capability plus separately versioned binding/overlay is a credible reuse model; credentials, sessions, logs, and evidence must remain tenant-scoped. | An `overrides` map keyed by every tenant inside the base artifact couples pooled logic to tenant identity, increases cross-tenant exposure, and creates an unbounded shared document. Keep overlays separate and validate them against a base artifact/version and narrow override schema. | I would duplicate a capability for a tenant if its steps, business semantics, or risk policy diverged materially—not merely its routes, labels, or locator bindings. |
| Put perceive/act/control-transfer behind a `Surface` seam. | **Endorse with narrower semantics.** Session handoff belongs to the surface/session layer, not the capability artifact. | A single locator list does not necessarily span web, UIA, AX, and pixels. Prefer logical target intent plus adapter-specific bindings; do not claim one web artifact runs on desktop without a binding and compatibility check. | I would keep control transfer outside `Surface` if the implementation has one session coordinator shared across adapters and the interface otherwise becomes a grab bag; the artifact should remain unaffected either way. |

### HITL/safety corrections before synthesis

1. Change unknown/missing risk from `safe` to validation failure or `confirm/deny`.
2. Clarify that CDP is an attachment/command transport, not a lock manager. Ownership is enforced by the project’s action arbiter; local physical input remains a documented demo limitation.
3. Sanitize the intervention example: replace raw goal/member IDs and concrete member URLs with a capability description plus opaque parameter/evidence references.
4. Split final replay outcome from recovery history.
5. Rephrase the PCI discussion. A strict project rule of “do not persist PAN-like values at all” is defensible, but it is a chosen data-minimization policy, not a claim that PCI forbids every truncated/tokenized representation. The cited storage controls expressly include truncation/tokenization among permitted unreadable forms.
6. Keep tenant overlays separate from the shared base artifact.

## 3. Independent §3.2 artifact completeness check

`brief_decomposition.md` includes every literal §3.2 item: successful-run emission; typed/serializable artifact; ordered actions; target identification; typed inputs; typed outputs/extraction; checkpoint/success condition; versioning; and human/agent reviewability. I found **no missing headline bullet**.

The following operational must-haves are present only implicitly and should be made explicit in the §3.2 minimum-proof table:

| Operational must-have to make explicit | Why it follows from §3.2 | Suggested proof language |
|---|---|---|
| Runnable agent-facing invocation contract, including stable capability identity/purpose and declared side effects | “Reusable,” “agent-invocable,” and understandable as to what it does/needs/returns require more than a schema-valid file. | A caller can enumerate or load the capability, validate typed arguments, invoke it by stable ID/version, and interpret its documented outputs/outcomes. |
| Explicit parameter bindings in actions and output extractor bindings | Merely declaring an input/output schema does not prove steps consume inputs or that returned values are extracted according to the declaration. | At least one action references a typed parameter placeholder, and at least one declared output names a deterministic extractor plus type validation. |
| Target resolution contract, not just locator storage | “How each target is identified” and robustness require uniqueness/context checks. | Each actionable target has a logical description, adapter binding/ranked candidates, expected cardinality/context, and fail-closed validation before action. |
| Structured checkpoint semantics tied to a step or terminal state | A free-text success sentence is serializable but not executable. | The artifact declares an executable assertion with target/expected predicate, timeout, and failure classification; replay evaluates it before reporting success. |
| Separate schema version from capability revision, plus artifact provenance/publication state | “Versioned” is ambiguous, and §3.2 permits emission only after success. | Store schema version and capability revision separately; link sanitized discovery provenance; reject incomplete/failed-discovery artifacts from executable publication. |
| Reviewable policy footprint | The calling agent/human must understand consequential behavior, while Project §3.4 applies to the artifact’s actions. | Artifact review shows required domains/routes/actions and per-step resolved risk without embedding credentials or example PII. |

These additions do not expand scope. They prevent a superficially typed JSON step list from passing the decomposition’s proof test without functioning as the clear capability contract Project §3.2 asks for.

## 4. Citation verification

Official pages were fetched directly on 2026-08-16:

1. **Anthropic computer use:** <https://platform.claude.com/docs/en/agents-and-tools/tool-use/computer-use-tool> verifies the beta computer tool, application-executed actions, iterative agent loop, dedicated VM/container guidance, domain allowlisting, and human confirmation for consequential actions. This supports its use as a discovery/safety reference, not as evidence of deterministic artifact replay.
2. **OpenAI computer use:** <https://developers.openai.com/api/docs/guides/tools-computer-use> verifies the three harness shapes (built-in screenshot/action loop, custom Playwright/Selenium/VNC/MCP tools, and code-execution harness), plus isolation, human oversight, and untrusted-page-content guidance. Model names on this live page are already mixed between overview and examples, so recommendations should remain version-agnostic.
3. **Playwright ARIA snapshots:** <https://playwright.dev/docs/aria-snapshots> verifies YAML accessibility representations, `page.ariaSnapshot()` / `locator.ariaSnapshot()`, and ARIA snapshot assertions. It does not establish that every legacy page has a useful accessibility tree.
4. **Playwright pause:** <https://playwright.dev/docs/api/class-page#page-pause> verifies that `page.pause()` stops script execution in headed mode until Resume is pressed or `playwright.resume()` is called. It does **not** provide exclusive ownership, remote control, or human-action auditing; those remain application responsibilities.

## Bottom line

Endorse the shared direction: hybrid real discovery, deliberate artifact compilation, model-free replay, fail-closed policy, typed outcomes, and a thin same-session handoff. The synthesis should carry forward the flip conditions above and correct the unsafe default-risk setting, overclaimed CDP ownership/auditing, unsanitized intervention sample, recursive recovery result, and in-artifact tenant override map.
